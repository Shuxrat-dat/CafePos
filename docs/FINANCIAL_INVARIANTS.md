# Финансовые инварианты Yurtora Cafe POS

Настоящий документ регламентирует правила расчёта денежных средств, проведения транзакций, списания сырья и закрытия смен, которые система обязана гарантировать программно и на уровне ограничений БД.

---

## 1. Заказы и ценообразование

1. **Типы данных и точность:**
   - Все финансовые вычисления производятся исключительно с использованием типа `Decimal`.
   - Использование типа `float` категорически запрещено на всех этапах (в БД, в Python-сервисах, в сериализации).
   - Суммы в сумах (UZS) округляются по правилам арифметики (`ROUND_HALF_UP`) до 1 сума (`Decimal('1')`).

2. **Неизменяемость исторических цен:**
   - При добавлении блюда в заказ цена фиксируется в строке заказа (`OrderItem.price = dish.price`).
   - Последующее изменение цены блюда в меню или тарифа модификатора не должно влиять на открытые и закрытые заказы.

3. **Формула расчёта итога:**
   $$\text{Subtotal} = \sum (\text{item.unit\_price} \times \text{item.quantity})$$
   $$\text{Discount} = \begin{cases} 
   \min(\text{Subtotal}, \text{round}(\text{Subtotal} \times \frac{\text{DiscountValue}}{100})), & \text{если процент} \\
   \min(\text{Subtotal}, \text{DiscountValue}), & \text{если сумма}
   \end{cases}$$
   $$\text{BaseForService} = \text{Subtotal} - \text{Discount}$$
   $$\text{Service} = \begin{cases} 
   \text{round}(\text{BaseForService} \times \frac{\text{ServicePercent}}{100}), & \text{если заказ в зале (dine\_in)} \\
   0, & \text{навынос / доставка}
   \end{cases}$$
   $$\text{Total} = \text{Subtotal} - \text{Discount} + \text{Service}$$
   - Налог (НДС) выделяется расчетно из итога для фискального чека (справочно, цены меню уже включают НДС):
     $$\text{VAT} = \text{round}\left(\text{Total} \times \frac{\text{VatPercent}}{100 + \text{VatPercent}}\right)$$

4. **Защита от изменений закрытых заказов:**
   - Заказ в статусе `PAID` или `CANCELLED` становится неизменяемым (`immutable`). Запрещено добавлять позиции, менять количества, применять скидки или удалять строки.

## 2. Платежи и транзакции

1. **Сущность платежа:**
   - Каждый платёж фиксируется отдельной неизменяемой транзакцией `Payment`.
   - Платёж имеет атрибуты: `order`, `cash_shift`, `amount`, `payment_method`, `status`, `created_at`, `cashier`, `idempotency_key`.

2. **Инвариант завершения оплаты:**
   - Заказ переходит в статус `PAID` тогда и только тогда, когда:
     $$\sum \text{Payment.amount (status=SUCCESS)} = \text{Order.total}$$
   - Недостаточная сумма не закрывает заказ (частичная оплата).
   - Избыточная сумма при безналичной оплате запрещена; при наличной оплате формируется сдача:
     $$\text{Change} = \text{CashReceived} - \text{CashDue}$$

3. **Идемпотентность финансовых команд:**
   - Запрос на приём оплаты должен сопровождаться уникальным заголовком/параметром `idempotency_key`.
   - Повторный вызов с тем же ключом не выполняет повторное списание, а возвращает результат исходной операции.

4. **Правила возвратов (Refunds):**
   - Возврат разрешён только для заказов в статусе `PAID`.
   - Совокупная сумма возвратов не может превышать сумму совершённых платежей:
     $$\sum \text{Refund.amount} \le \sum \text{Payment.amount}$$
   - Исходный платёж не удаляется; возврат оформляется компенсирующей проводкой с отрицательным финансовым знаком.

## 3. Кассовые смены (Cash Shifts)

1. **Обязательность смены:**
   - Ни одна кассовая операция (приём оплаты наличными, выплата сдачи, внесение, инкассация, возврат) не может быть проведена без открытой смены `CashShift`.
   - В один момент времени на одной физической кассе может быть открыта только одна смена.

2. **Баланс наличности смены:**
   $$\text{ExpectedCash} = \text{InitialCash} + \sum \text{CashIn} - \sum \text{CashOut} + \sum \text{CashPayments} - \sum \text{CashRefunds}$$
   - При закрытии смены кассир вводит сумму фактического пересчёта наличности (`ActualCash`).
   - Расхождение фиксируется документально:
     $$\text{Difference} = \text{ActualCash} - \text{ExpectedCash}$$
   - Повторное закрытие уже закрытой смены запрещено.

---

## 4. Складской учёт и сырьевой баланс

1. **Неразрывность складского следа:**
   - Поле `Product.stock` не должно изменяться произвольными SQL `UPDATE` в обход таблицы `StockMovement`.
   - Каждое движение обязано содержать:
     - `kind` (приход, списание, продажа, инвентаризация);
     - `quantity` (с корректным знаком);
     - `unit_cost` (себестоимость за единицу на момент проводки);
     - ссылку на документ-основание (заказ `Order`, акт списания, инвентаризационную ведомость).

2. **Однократность списания:**
   - Списание по заказу происходит ровно один раз при переводе заказа в статус `PAID`.
   - Запрещено повторное автоматическое списание при повторном открытии/просмотре чека.

3. **Конкурентная изоляция:**
   - Изменение остатков продуктов при списании заказа должно выполняться внутри атомарной транзакции с блокировкой строк сырья (`select_for_update`) для исключения гонок при параллельных заказах.
