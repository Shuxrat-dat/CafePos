# Исследование фискализации и интеграции с Soliq.uz (ОФД Узбекистан)

## 1. Законодательная база и регуляторные требования

В Республике Узбекистан применение онлайн контрольно-кассовой техники (онлайн-ККМ) и виртуальных касс регулируется:
- **Постановлением Кабинета Министров РУз № 943 от 23.11.2019 г.** «О мерах по обеспечению применения онлайн контрольно-кассовых машин и системы виртуальных касс».
- Требованиями **Государственного налогового комитета РУз (ГНК / Soliq.uz)** и Государственного реестра онлайн-ККМ и виртуальных касс.

### Ключевые требования к фискальному чеку:
1. **QR-код** с зашифрованной ссылкой на проверку чека на сервере оператора фискальных данных (ОФД / Soliq.uz).
2. **Фискальный признак** (ФП) и номер фискального документа (ФД).
3. **Заводской / серийный номер** фискального модуля (ФМ) или фискального регистратора.
4. **ИНН / ПИНФЛ** налогоплательщика (юрлица или индивидуального предпринимателя).
5. **ИКПУ (Индивидуальный классификатор продукции и услуг / MXIK кодировка)** для каждой товарной позиции или блюда (например, код ресторанных блюд или безалкогольных напитков).
6. **Единицы измерения** согласно единому классификатору (порция, шт, литр, кг).
7. **Ставки налогообложения** (НДС: 12% или «без НДС»).
8. **Способ оплаты**: наличные, безналичные (банковская карта / Uzum / Click / Payme / HUMO / Uzcard).

## 2. Архитектура интеграции с фискальными операторами

В соответствии с правилами проекта: **не утверждать, что интеграция с Soliq.uz реализована или готова к продакшну без физического фискального регистратора или аккредитованной виртуальной кассы**.

Прямого открытого публичного REST API у `soliq.uz` для произвольной генерации фискальных признаков без сертифицированного фискального модуля **не существует**. Фискализация в Узбекистане выполняется одним из трёх стандартных путей:

### Вариант А: Интеграция с физическим фискальным регистратором (ФР)
- Примеры оборудования: **Штрих-М-UZ, Меркурий, Datecs, Daisy**.
- Протокол: драйвер OPOS / ESC-POS / локальный TCP-сокет на кассовом терминале.
- POS-система отправляет структуру чека в локальный сервис печати/драйвер, ФР отправляет данные в ОФД и печатает фискальный чек с QR-кодом.

### Вариант Б: Сертифицированная виртуальная касса (Cloud / Local Kassa)
- Примеры операторов: **ReKassa, E-Pos, Multikassa, Click Kassa, Payme Kassa**.
- Протокол: REST API облачного провайдера виртуальной кассы, авторизованного ГНК РУз.
- Запрос отправляется на шлюз виртуальной кассы, шлюз подписывает чек сертификатом ЭЦП юридического лица (или SAM-модулем) и регистрирует в Soliq.uz, возвращая URL QR-кода и фискальный номер.

## 3. Архитектурный интерфейс в Yurtora Cafe (POS)

Для того чтобы бизнес-логика POS-системы была полностью готова к подключению любого оператора без переписывания модулей оплаты, создаётся абстрактный адаптер:

```python
class FiscalReceiptData:
    def __init__(self, order, payment):
        self.order_id = order.id
        self.receipt_number = f"CHK-{order.id}"
        self.cashier_name = order.cashier.get_full_name() or order.cashier.username
        self.items = [
            {
                "name": item.dish.name,
                "mxik_code": getattr(item.dish, "mxik_code", "05601001001000000"),
                "quantity": item.quantity,
                "price": item.price,
                "line_total": item.line_total,
                "vat_percent": 12,
            }
            for item in order.items.all()
        ]
        self.total = order.total
        self.payment_method = payment.payment_method


class BaseFiscalProvider:
    def register_receipt(self, receipt_data: FiscalReceiptData) -> dict:
        """Отправляет чек на фискализацию. Возвращает dict с полями:
        - fiscal_sign (ФП)
        - fiscal_doc_number (ФД)
        - qr_code_url (ссылка для QR-кода Soliq.uz)
        - status (SUCCESS / ERROR)
        """
        raise NotImplementedError

    def register_refund(self, refund_data) -> dict:
        """Регистрирует чек возврата в ОФД."""
        raise NotImplementedError
```

### Мок-провайдер для тестов и разработки (`MockFiscalProvider`):
В режиме разработки система эмулирует фискализацию: генерирует тестовый QR-код со ссылкой на верификатор `https://ofd.soliq.uz/check?fiscal_sign=...`, позволяя верстать и тестировать чеки на термопринтере без боевого оборудования.

## 4. Необходимые подготовительные шаги для запуска боевой фискализации
1. Заключение договора с оператором фискальных данных (ОФД) в Узбекистане.
2. Получение ЭЦП юридического лица (ЮЛ) и регистрация торговой точки в персональном кабинете налогоплательщика на `my.soliq.uz`.
3. Заполнение кодов ИКПУ (MXIK) для всех блюд меню в модели `Dish` (добавить поле `mxik_code` с валидацией 17-значного цифрового кода).
4. Настройка связи с локальным агентом фискального регистратора или API виртуальной кассы.
