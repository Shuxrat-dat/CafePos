# CafePOS

POS-система для кафе и ресторанов: зал и столы, касса, кухня, заказы, меню, склад, персонал, отчёты.
Интерфейс на узбекском (основной) и русском языках, суммы в сумах (UZS).

Стек: Django 6.1, HTMX, Tailwind (локальный `static/js/tailwind.js`), SQLite или PostgreSQL, waitress.
Новых зависимостей не добавлялось — см. `requirements.txt`.

## Быстрый старт: демо для презентации

```bat
start_demo.bat
```

Скрипт создаёт `.venv` (при первом запуске), применяет миграции, заполняет **отдельную** демо-базу
`demo.sqlite3` рестораном «Cafe Demo» (только если она пустая) и запускает сервер на `http://127.0.0.1:8000`.
Рабочая база `db.sqlite3` / PostgreSQL в демо-режиме не используется.

Вход: на странице входа есть кнопки «Быстрый вход в демо» для каждой роли. Сценарий показа — в [docs/DEMO.md](docs/DEMO.md).

Сброс демо после презентации: **Настройки → Восстановить демо-данные** (только в демо-режиме) или

```bat
set CAFEPOS_DEMO=1 && .venv\Scripts\python.exe manage.py seed_demo --reset
```

## Рабочий запуск

1. Скопируйте `.env.example` в `.env`, задайте `DJANGO_SECRET_KEY` и `DJANGO_ALLOWED_HOSTS`.
2. `.venv\Scripts\python.exe manage.py migrate`
3. `.venv\Scripts\python.exe manage.py createsuperuser` — владелец; сотрудников добавляйте в разделе «Персонал».
4. `start_server.bat` (collectstatic + waitress на порту 8000).

Резервная копия базы: `backup.bat` (команда `backup_db`).

## Разделы и роли

| Раздел | Владелец / Админ | Кассир | Официант | Повар |
|---|---|---|---|---|
| Зал, заказы, пречек | все заказы | все заказы | только свои | — |
| Оплата, скидки, чеки | да | да | — | — |
| Кухня | да | — | — | да |
| Меню, склад, отчёты, персонал, настройки | да | — | — | — |

Права проверяются на сервере: middleware по адресу страницы (`accounts/middleware.py`) и проверки в каждом действии.
Список ролей и прав — в одном файле `accounts/permissions.py`.

## Что где

- `pos/` — зал, экран заказа, оплата, чек, страница заказов. Бизнес-правила (суммы, скидки, оплата, кухня) — в `pos/services.py`.
- `kitchen/` — экран кухни (те же заказы, что и на кассе).
- `menu/` — меню для гостей, QR-коды, управление меню (`manage_views.py`).
- `inventory/` — склад: приход, списание, инвентаризация, движение; списание по техкартам при оплате (`services.py`).
- `reports/` — панель владельца.
- `core/` — настройки заведения, язык интерфейса, иконки и форматы (`templatetags/ui.py`), персонал, демо-режим.

## Расчёт суммы заказа

`подытог − скидка (процент или сумма) + обслуживание (% от суммы после скидки, только для заказов в зале) = итог`.
Процент обслуживания запоминается в заказе при создании, поэтому смена настроек не меняет старые заказы.
НДС в чеке выводится справочно как часть итога. Все суммы округляются до целых сумов.

## Переводы

Исходные строки — на русском, перевод — `locale/uz/LC_MESSAGES/django.po`. GNU gettext не нужен:

```bat
.venv\Scripts\python.exe manage.py make_translations            :: добавить новые строки в uz
.venv\Scripts\python.exe manage.py make_translations --locale ru :: обновить исходный каталог
.venv\Scripts\python.exe manage.py compile_translations         :: собрать .mo
```

Названия блюд, категорий, залов и продуктов переводятся полями `name_uz` в самих записях.
